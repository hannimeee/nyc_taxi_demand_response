# MAST30034 Project 1: Impact of MTA Subway Disruptions on FHVHV Demand Response

This repository contains the code for MAST30034 Project 1. The project investigates how MTA subway disruptions affect demand response in New York City's high-volume for-hire vehicle (FHVHV) market, using average request-to-pickup wait time as the main response variable.

The analysis combines TLC FHVHV trip records, MTA subway ridership, MTA subway service alerts, weather data, and TLC taxi zone information. The final analysis is conducted at taxi zone-hour granularity from January 2025 to May 2026.

## Research Question

How do MTA subway disruptions affect the demand response of FHVHV services across New York City, and how can this inform more spatially and temporally targeted dispatch strategies?

## Running the Project

Run the notebooks in numerical order. Each notebook depends on outputs generated by earlier notebooks. Running them out of order may cause missing file or missing table errors.

```
01_fetch_data.ipynb
02_preprocess_data.ipynb
03_feature_engineering.ipynb
04_exploratory_analysis.ipynb
05_geospatial_temporal_analysis.ipynb
06_statistical_modelling_1.ipynb
07_statistical_modelling_2.ipynb
```

## Notebook Overview

- `01_fetch_data.ipynb`: downloads TLC trip records, MTA ridership, MTA service alerts, weather data, and TLC taxi zone files.
- `02_preprocess_data.ipynb`: cleans raw datasets and removes invalid records.
- `03_feature_engineering.ipynb`: aggregates datasets to taxi zone-hour level and constructs the final feature table.
- `04_exploratory_analysis.ipynb`: explores distributions, correlations, and broad relationships between taxi demand, ridership, alerts, and wait time.
- `05_geospatial_temporal_analysis.ipynb`: analyses spatial and temporal patterns in disruptions, trips, ridership, and wait time.
- `06_statistical_modelling_1.ipynb`: fits a weighted least squares linear regression model to explain disruption effects on FHVHV wait time.
- `07_statistical_modelling_2.ipynb`: fits a residual Gradient Boosted Tree model and constructs alert-aware dispatch priority analysis.

## Notes on Runtime

The TLC trip records are large (especially FHVHV), so preprocessing and feature engineering notebooks may take a long time to run. Intermediate outputs are saved under `data/processed/`, `data/features/`, and `data/analysis/` to avoid recomputing all steps unnecessarily.
